# Mattermost — Self-Hosted Intranet Deployment

A production-ready, **intranet-first** Mattermost deployment using Docker Compose.  
Designed to coexist on the same Linux VPS as an existing **Mine-Ops** stack without any port or network conflicts.

---

## Features

- ✅ Works fully offline / on an internal network (no internet dependency)
- ✅ No port conflicts with Mine-Ops (`5432`, `8000`, `5173` untouched)
- ✅ Isolated Docker bridge network (`mattermost-net`)
- ✅ Nginx reverse proxy with TLS 1.2 / 1.3 (self-signed internal CA)
- ✅ Self-hosted push proxy (gracefully degrades without FCM / internet)
- ✅ Android client–friendly (custom server URL + CA cert install)
- ✅ Tuned for a VPS with ~7 GB RAM, 100 GB storage, 2 Xeon cores

## Deployment

### 1. Clone the repository

```bash
git clone https://github.com/your-org/mattermost-chat.git
cd mattermost-chat
```

### 2. Configure environment variables

```bash
cp .env.example .env
nano .env          # set DOMAIN, MM_DB_PASSWORD, and optionally FCM_API_KEY
```

| Variable | Description | Default |
|----------|-------------|---------|
| `DOMAIN` | Internal FQDN for Mattermost | `chat.company.internal` |
| `MM_DB_PASSWORD` | PostgreSQL password for `mmuser` | _(change this!)_ |
| `FCM_API_KEY` | Firebase Cloud Messaging key for Android push | `placeholder` |

### 3. Generate TLS certificates

```bash
chmod +x scripts/gen-certs.sh
./scripts/gen-certs.sh chat.company.internal
```

This creates `nginx/certs/ca.crt`, `server.crt`, and `server.key`.

### 4. Deploy the stack

```bash
chmod +x scripts/deploy.sh
./scripts/deploy.sh
```

The script pulls images, starts all containers, and prints the URL.

## Android Client Setup

1. Copy `nginx/certs/ca.crt` to your Android device (USB, email, etc.)
2. **Settings → Security → Install a certificate → CA certificate** — select `ca.crt`
3. Open the Mattermost app → **Enter Server URL** → `https://chat.company.internal`
4. The app will trust your internal CA and connect successfully

## Port Map (coexistence with Mine-Ops)

| Service | Host port | Notes |
|---------|-----------|-------|
| Nginx HTTP | **80** | Redirects to HTTPS |
| Nginx HTTPS | **443** | Mattermost entry point |
| `mm-postgres` | _none_ | Internal only — no host binding |
| Mine-Ops postgres | 5432 | Unchanged |
| Mine-Ops backend | 8000 | Unchanged |
| Mine-Ops frontend | 5173 | Unchanged |

## Backup

```bash
chmod +x scripts/backup.sh
./scripts/backup.sh
```

Saves a gzipped PostgreSQL dump **and** a tar of the `mattermost-data` volume to `./backups/` with a timestamp.

## Intranet / Offline Operation

- Mattermost itself never requires internet access.
- The push proxy attempts FCM delivery but **silently skips** it when the key is a placeholder or the network is unavailable — the server continues running normally.
- Email notifications are disabled by default (`MM_EMAILSETTINGS_SENDEMAILNOTIFICATIONS=false`).  
  Enable and point to an internal SMTP relay if needed.
